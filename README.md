# Проект Скайр (Skyr): Моностатический измеритель ВНГО (CloudCam)

Аппаратно-программный комплекс для пассивного оптического измерения высоты нижней границы облачности (ВНГО), скорости и направления ее движения, а также общего балла облачности. 

Система разработана на основе моностатического метода С.В. Зуева и использует две камеры, расположенные вплотную (на малом базисе), но оснащенные объективами с разными фокусными расстояниями (например, с углами обзора 120° и 160°). За счет разницы в масштабе и использования стереоскопических алгоритмов система вычисляет расстояние до облачного фрагмента, а оптический поток позволяет определить параметры ветра.

---

## 1. Требования к оборудованию

Для сборки комплекса вам потребуются:
*   **Вычислительный модуль:** Raspberry Pi 5 (или 4) с установленной Raspberry Pi OS.
*   **Камеры:** 2× модуля ESP32-CAM (рекомендуются сенсоры OV2640 или OV5640) со сверхширокоугольными линзами (120° — `cam120` и 160° — `cam160`).
*   **Питание:** Стабильный источник 5V (рекомендуется DC-DC преобразователь), общая "земля" (GND).
*   **Дополнительно:** USB-TTL программатор (3.3V) для прошивки ESP32-CAM, калибровочный шаблон (шахматная доска 9x6).
*   **Монтаж:** Жесткая рама для фиксации камер с оптическими осями, направленными строго в зенит, и известным базисным расстоянием (рекомендуется ~0.8–1.0 м).

---

## 2. Структура проекта

Файловая система на Raspberry Pi разделена на директории сервера, обработки и хранения изображений:

*   `/opt/cloudcam/server/` — Сервер-координатор (Flask/Gunicorn). Содержит `app.py`, `config.json`, `requirements.txt`.
*   `/opt/cloudcam/processing/` — Скрипты калибровки и вычисления ВНГО:
    *   `cbh_compute.py` — основной алгоритм расчета ВНГО.
    *   `cbh_gui.py` — веб-интерфейс / панель мониторинга.
    *   `calib/capture_calib_pairs.py` — сбор калибровочных пар.
    *   `calib/calibrate_fisheye_single.py` — расчет внутренних параметров (intrinsics).
    *   `calib/calibrate_fisheye_stereo.py` — расчет внешних параметров (extrinsics).
    *   `calib_out/` — директория для YAML-файлов с результатами калибровки.
*   `/var/lib/cloudcam/` — Хранилище данных:
    *   `cam120/` и `cam160/` — полученные JPEG-изображения и JSON-метаданные.
    *   `stereo_calib/`, `cam120_calib/`, `cam160_calib/` — кадры для калибровки.
    *   `results/` — результаты работы (`vnogo.csv`, `vnogo.jsonl`).

## 3. Инструкция по развертыванию (Deployment Guide)

### Шаг 1. Настройка Raspberry Pi (Точка доступа и сервер)
1. **Поднимите Wi-Fi AP** (CloudCamAP), чтобы ESP32-CAM могли подключаться локально.
2. **Установите системные зависимости:**
   ```bash
   sudo apt update
   sudo apt install -y python3 python3-pip python3-venv
   ```
   *Замечание:* системные пакеты или виртуальные окружения необходимы для обхода ошибки `externally-managed-environment` (PEP 668).
3. **Разверните структуру сервера:**
   ```bash
   sudo mkdir -p /opt/cloudcam/server
   sudo chown -R pi:pi /opt/cloudcam
   cd /opt/cloudcam/server
   python3 -m venv venv
   ./venv/bin/pip install -r requirements.txt
   ```
   Подготовьте каталоги для данных:
   ```bash
   sudo mkdir -p /var/lib/cloudcam/cam120 /var/lib/cloudcam/cam160 /var/lib/cloudcam/results
   sudo chown -R pi:pi /var/lib/cloudcam
   ```
  
4. **Настройте автозапуск сервера (systemd):**
   Скопируйте `cloudcam.service` в `/etc/systemd/system/`, затем выполните:
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable cloudcam.service
   sudo systemctl restart cloudcam.service
   ```
   Проверьте статус: `curl http://192.168.4.1:8000/health` (должен вернуть JSON `status: ok`).

### Шаг 2. Прошивка ESP32-CAM
1. Подключите ESP32-CAM к USB-TTL: `5V ↔ 5V`, `GND ↔ GND`, `U0T ↔ RX`, `U0R ↔ TX`. Для входа в режим прошивки замкните `IO0` на `GND` и нажмите RESET.
2. Откройте проект в PlatformIO (`esp32cam_vngo`). Убедитесь, что в `platformio.ini` включен параметр `BOARD_HAS_PSRAM`.
3. В исходном коде (`main.cpp`) настройте параметры подключения:
   * `WIFI_SSID = "CloudCamAP"`
   * Для камеры 120° установите `CAM_ID = "cam120"`, для камеры 160° — `CAM_ID = "cam160"`.
   * Убедитесь, что `CAPTURE_PERIOD_SEC = 600` (строго 10 минут) и настроен переход в Deep Sleep.
4. Прошейте каждую камеру поочередно. После загрузки уберите перемычку `IO0` и перезагрузите модули.

## 4. Калибровка камер (Критический этап)
Камеры со сверхширокоугольными объективами имеют сильную бочкообразную дисторсию (fisheye-искажения). Без жесткой калибровки метод работать не будет.

1. **Подготовка:** Распечатайте PDF с шахматной доской (9х6 внутренних углов), жестко закрепите мишень на плоской поверхности.
2. **Сбор данных:** Разместите доску перед камерами на разных расстояниях и под разными ракурсами. Система должна отработать 20–40 циклов, захватывая доску.
3. **Сохранение пар:** Запустите скрипт сортировки калибровочных пар:
   ```bash
   python3 /opt/cloudcam/processing/calib/capture_calib_pairs.py --n 30
   ```
   *Скрипт отберет синхронные кадры в папки `stereo_calib`, `cam120_calib`, `cam160_calib`.*
4. **Расчет внутренних параметров (K, D):**
   ```bash
   python3 /opt/cloudcam/processing/calib/calibrate_fisheye_single.py # Для cam120
   python3 /opt/cloudcam/processing/calib/calibrate_fisheye_single.py # Для cam160
   ```
   *Результаты сохранятся в `calib_out/cam120_fisheye.yml` и `cam160_fisheye.yml`.*
5. **Расчет внешних параметров (R, T):**
   ```bash
   python3 /opt/cloudcam/processing/calib/calibrate_fisheye_stereo.py
   ```
   *Результат: `calib_out/stereo_fisheye.yml`.*

## 5. Расчет параметров и запуск мониторинга

### Определение ВНГО
После успешной калибровки система готова к измерению ВНГО. Алгоритм `cbh_compute.py` использует модель `cv.fisheye.stereoRectify` для выпрямления кадров, находит сопряженные точки алгоритмом ORB, фильтрует ложные соответствия с помощью RANSAC и выполняет триангуляцию. ВНГО рассчитывается как нижний перцентиль глубин 3D-точек в центральной зоне кадра.

Для ручного запуска расчета выполните:
```bash
python3 /opt/cloudcam/processing/cbh_compute.py
```
*Данные сохранятся в `vnogo.csv` и `vnogo.jsonl`.*

### Веб-панель (GUI)
Комплекс оснащен современной асинхронной веб-панелью на базе фреймворка NiceGUI (запускается через `cbh_gui.py`). Интерфейс предоставляет возможности для мониторинга вычисленных значений ВНГО, просмотра логов телеметрии и графиков, а также удаленного обновления прошивок (OTA).

### Определение скорости и направления ветра
Движение облачности рассчитывается оптическим потоком. Рекомендуется метод FFT Phase Correlation из репозитория Waggle (кросс-корреляция в частотной области). Полученный в пикселях сдвиг конвертируется в м/с на основе данных о ВНГО, физическом размере пикселя сенсора и фокусном расстоянии объектива.

## 6. Решение типовых проблем

* **Зависания ESP32 (WDT / Capture FAILED / EV-EOF-OVF):**
  Убедитесь, что используется неблокирующее чтение HTTP с тайм-аутами. Снизьте тактовую частоту сенсора (`xclk_freq_hz`) до 10 МГц, установите `frame_size` на `QVGA` или `VGA` и `fb_count=1` или 2.
* **Проблемы с Long-poll координацией на сервере:**
  Если сервер зависает в ожидании снимков, проверьте работоспособность `gunicorn` (`/etc/systemd/system/cloudcam.service`).
* **Неточность расчета триангуляции:**
  Стереопараллакс при сверхшироких линзах (120/160°) и малом базисе очень мал. Обязательна точная калибровка `fisheye`. При необходимости увеличьте базис до ~0.8–1 м и убедитесь, что оптические оси направлены строго в зенит.
* **Работа в ночное время:**
  Модули OV2640/OV5640 испытывают трудности с распознаванием облачных текстур ночью без подсветки луны. Этот режим имеет ограничения и требует отдельной конфигурации экспозиции или использования инфракрасной камеры.
